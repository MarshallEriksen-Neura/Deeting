## 这页讲什么

这页关注的是插件“怎么发布”，而不是“怎么写代码”。

如果你已经有一个基本可运行的插件，想把它送到 Deeting 的发布入口，这页就是下一步。

## 发布前你至少应该确认这些事

在发布之前，建议先确认：

1. `deeting.json` 已经写完整
2. `llm-tool.yaml` 与 `main.py` 已同步
3. `SKILL.md` 与当前行为一致
4. 插件目录结构清晰，没有明显残留模板内容
5. 你的插件仓库已经推送到 GitHub

## 推荐发布路径

当前推荐路径是：

1. 在本地完成插件开发
2. 把插件代码推送到 GitHub 仓库
3. 复制仓库 URL
4. 进入 `Deeting Dashboard > Developer Lab`
5. 粘贴 GitHub URL
6. 点击 `Publish`

这条路径来自当前仓库里插件开发套件的发布说明，是现在最清晰的公开发布入口。

## 发布前应该重点检查什么

### `deeting.json`

确认：

- `id`、`name`、`version`、`description` 合理
- `entry` 指向真实存在的文件
- `permissions` 没有多申请
- `capabilities` 指向真实契约文件

### `llm-tool.yaml`

确认：

- 工具名正确
- 描述清晰
- 参数结构与实现一致

### `main.py`

确认：

- 能处理当前工具名
- 参数读取与契约一致
- 返回结构符合预期

### `SKILL.md`

确认：

- 工具名没写错
- 说明没有滞后
- 已写清楚边界和注意事项

## 一个很容易被忽略的问题

很多插件“能跑”，但并不适合发布。

常见原因包括：

- 还是模板名、模板文案
- 行为说明和实现不一致
- 工具描述太模糊
- 权限申请过大
- 发布前没有清理掉实验性代码

所以，发布前最好把插件当成“别人第一次看到的产品”重新检查一遍。

## 发布后建议做什么

发布不是终点，建议后续继续做这些事：

- 跟踪版本号
- 修正文档说明
- 根据使用情况优化工具边界
- 保持 `deeting.json`、`llm-tool.yaml`、`main.py`、`SKILL.md` 长期同步
