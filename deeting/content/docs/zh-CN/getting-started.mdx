## Deeting 是什么

谛听 Deeting 是一个智能上下文与记忆中枢。

它的目标不是只提供一个聊天窗口，而是把对话、记忆、知识、工具调用与运行时能力组织在一起，让你在处理复杂任务时不必反复切换上下文，也不必每次都从零开始。

如果你第一次接触 Deeting，可以先把它理解成一个同时具备以下特点的产品：

- 它能作为日常对话与任务执行入口
- 它能连接模型、工具、插件和 MCP 能力
- 它关注上下文连续性，而不是一次性问答
- 它既有网页端，也有更贴近本地运行时的桌面端

## 适合谁

如果你属于下面这些人，这份文档会很适合你：

- 想快速理解 Deeting 是什么、该从哪里开始的普通用户
- 想用桌面端获得更强本地能力的重度使用者
- 想把 API、MCP 或扩展能力接进现有流程的开发者
- 想从产品和工程两侧理解 Deeting 的贡献者

## 第一次使用建议怎么开始

建议按下面的顺序体验：

1. 创建账号或登录现有账号
2. 从聊天入口开始，先熟悉基础交互方式
3. 查看当前可用的助手、模型或能力入口
4. 如果你需要更贴近本地运行时的体验，再尝试桌面端
5. 如果你准备接入外部能力，再继续阅读集成与开发文档

## 你通常会在哪些区域工作

- `Chat`
  这是最常用的入口。你可以在这里发起问题、执行任务，并与能力调用过程产生交互。

- `Assistants`
  用来选择、切换或管理更具任务导向的助手形态。

- `Docs`
  用来查看公开使用文档、开发说明、集成方式和版本更新。

- `Dashboard`
  用来进入更细的配置与管理区域，例如个人设置、日志、知识、插件与其他能力面板。

## 第一次使用时最值得先理解的事

在继续深入之前，建议你先理解这三个概念：

1. `网页端` 和 `桌面端` 并不完全等价  
   桌面端会接入更多本地运行时相关能力，但这也意味着它可能有额外的权限、审批或环境前提。

2. `配置存在` 不等于 `运行时已打通`  
   某些功能在界面上看起来已经出现，但真正可用还依赖模型、插件、MCP、审批链路或本地环境。

3. `文档分层` 是有意设计的  
   使用文档讲“怎么成功使用”，开发文档讲“怎么理解和接入”，而 `Ideas / RFC` 则只代表探索中的方向。

## 如果你只想快速开始

最短路径可以这样走：

1. 登录
2. 打开 `Chat`
3. 完成一次基础任务
4. 根据需要决定是否安装或使用桌面端
5. 遇到边界问题时，先看对应文档而不是直接猜测产品行为
