## Who this page is for

Start here if your goal is to build a Deeting plugin.

Plugin development is usually narrower than core platform development. In most cases, you want to:

- expose a callable tool
- connect an external or internal capability
- optionally render a custom UI
- package everything in the standard Deeting plugin structure

## Environment preparation

Before you start, prepare these on your machine:

- `Node.js`
  Needed for scaffolding, frontend assets, and parts of the toolchain.

- `Python`
  The default plugin template uses `main.py` as the backend entrypoint.

- `Bun`
  The recommended way to start a plugin is:

  ```bash
  bunx create-deeting-plugin
  ```

- `Windows + WSL`
  If you are developing on Windows, install WSL first. It tends to provide a more stable path for Python, Node, scaffolding, and local dev tooling in this ecosystem.

## Fastest path to a first plugin

1. Install Node.js, Python, and Bun
2. On Windows, prepare WSL first
3. Run `bunx create-deeting-plugin`
4. Define the tool contract
5. Implement `main.py`
6. Add behavior guidance and optional UI last

## Scaffold with `create-deeting-plugin`

Recommended command:

```bash
bunx create-deeting-plugin
```

It creates a standard plugin directory so you do not have to invent the structure yourself.

## What the scaffold gives you

A standard plugin usually includes:

- `deeting.json`
  metadata, permissions, entrypoints, and capability declarations

- `main.py`
  backend implementation, centered around:

  ```python
  async def invoke(tool_name, args, deeting):
      ...
  ```

- `llm-tool.yaml`
  the callable host tool contract

- `SKILL.md`
  behavioral guidance and constraints

- `ui/index.html`
  optional frontend rendering

## Understand the responsibility of each file

- `llm-tool.yaml`
  defines what is callable

- `main.py`
  implements how it runs

- `SKILL.md`
  explains how and when it should be used

- `deeting.json`
  describes the plugin package itself

- `ui/index.html`
  handles frontend presentation if needed

## Most important rule: keep them in sync

If you change the tool name, parameters, or behavior, update these together:

1. `llm-tool.yaml`
2. `main.py`
3. `SKILL.md`

Recommended order:

1. update the contract
2. update the implementation
3. update the guidance

## A safe development sequence

1. Keep the plugin focused on one job
2. Define the smallest useful parameter set in `llm-tool.yaml`
3. Implement the minimal happy path in `main.py`
4. Validate the returned output
5. Add `ui/index.html` only if the plugin needs custom rendering
6. Document usage and constraints in `SKILL.md`
