## What this page covers

This page is about shipping a plugin, not writing one from scratch.

If your plugin already works locally and you want to move toward publishing, this is the next step.

## Pre-publish checklist

Before publishing, confirm:

1. `deeting.json` is complete
2. `llm-tool.yaml` and `main.py` are in sync
3. `SKILL.md` matches current behavior
4. the package no longer contains obvious template leftovers
5. the repository is pushed to GitHub

## Recommended publishing path

The current recommended path is:

1. finish local plugin development
2. push the plugin to GitHub
3. copy the repository URL
4. open `Deeting Dashboard > Developer Lab`
5. paste the GitHub URL
6. click `Publish`

This matches the current publishing guidance in the plugin development kit.

## What to verify before publishing

### `deeting.json`

Verify:

- identity and version fields are correct
- entrypoints point to real files
- permissions are still minimal
- capabilities point to the real callable schema

### `llm-tool.yaml`

Verify:

- tool names are correct
- descriptions are clear
- parameters match implementation

### `main.py`

Verify:

- it handles the current tool names
- argument handling matches the schema
- outputs are shaped as expected

### `SKILL.md`

Verify:

- names are current
- guidance is not stale
- limits and expected usage are documented

## A common mistake

Many plugins are runnable but not yet publishable.

Typical reasons:

- template names still remain
- descriptions are vague
- docs and code disagree
- permissions are too broad
- experimental code was never cleaned up
