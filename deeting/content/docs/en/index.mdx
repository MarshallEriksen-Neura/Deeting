## What you can find here

- Product onboarding and first-run guidance
- Desktop capabilities and boundary notes
- Developer setup and repository orientation
- Integration guidance for APIs, MCP, and plugins
- Release notes and compatibility updates

## Best starting points

- `Users`
  Start with [Getting Started](./getting-started).

- `Desktop-focused users`
  Read [Desktop Features](./desktop-features) first.

- `Developers`
  If you want to build plugins, start with [Plugin Development Guide](./plugin-development-guide).

## Environment notes for developers

If you plan to develop plugins or work on local capability flows, prepare:

- Node.js
- Python
- Bun
- WSL first if you are on Windows

See [Plugin Development Guide](./plugin-development-guide) for the full setup path.

## Recommended reading order

1. Read [Why Deeting Is Named Diting](./brand-story)
2. Start with [Getting Started](./getting-started)
3. Continue with [Desktop Features](./desktop-features)
4. For plugin authors, read [Plugin Development Guide](./plugin-development-guide)
5. Use [Integration](./integration) when connecting systems
6. Read [Developer Guide](./developer-guide) when contributing

## Public scope

This hub is public. The `Ideas / RFC` area is intentionally marked experimental so readers can distinguish stable guidance from work in progress.
