## What this page covers

If your plugin includes a frontend, this page explains the basic UI contract.

In the current template, the frontend entry is usually:

```text
ui/index.html
```

This file is not just a static HTML page. It participates in a message-based handshake with the host.

## Why a plugin UI needs a handshake

The host does not simply inject data into the page by default.  
Instead, the UI runs in a controlled environment and exchanges state with the host through messages.

That means:

- the page should signal when it is ready
- the host sends data only after that signal
- theme changes are also delivered through messages

## Core flow in the template

The template effectively follows this sequence:

1. the host loads `ui/index.html`
2. the UI sends `DEETING_PLUGIN_READY`
3. the host sends data into the page
4. the UI renders once data arrives

## Message types in the current template

The template listens for:

- `DEETING_DATA`
- `DEETING_THEME_CHANGE`

And it sends:

- `DEETING_PLUGIN_READY`

## Minimal handshake example

```javascript
window.addEventListener('message', (event) => {
  const { type, payload, title } = event.data;

  if (type === 'DEETING_DATA') {
    render(payload, title);
  }

  if (type === 'DEETING_THEME_CHANGE') {
    document.documentElement.classList.toggle('dark', payload === 'dark');
  }
});

window.parent.postMessage({ type: 'DEETING_PLUGIN_READY' }, '*');
```

## What a minimal UI should do

A minimal usable plugin UI should:

1. send the ready signal after load
2. receive and render host data
3. show a sensible initial state before data arrives
4. react to theme changes

## Common mistakes

1. forgetting to send `DEETING_PLUGIN_READY`
2. showing a blank page while waiting for data
3. ignoring theme updates
4. assuming a payload shape that no longer matches `main.py`

## How the UI should work with the backend

The frontend should be designed around the output returned by `main.py`.

A healthier workflow is:

1. define the backend response shape
2. render that shape in the frontend
3. update both when the shape changes

Do not treat the frontend and backend as unrelated pieces.

## If you want a richer UI

The template `ui/index.html` is a starting point, not a limit.

You can extend it with:

- richer layout
- cards and charts
- multiple sections
- loading, empty, and error states

But even in a more advanced UI, the handshake and message-based sync still need to remain in place.
