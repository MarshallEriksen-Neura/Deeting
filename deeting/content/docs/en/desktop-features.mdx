## Why the desktop app matters

The desktop app is not just a wrapper around the web app.

It exists to provide a more local-runtime-oriented experience, including system integration, tray and window behavior, selected local execution paths, and parts of the product that work better when they stay close to the machine.

## Key capabilities today

- Local chat and runtime orchestration
- System tray behavior, close guards, and desktop notifications
- Selected local knowledge and execution paths
- Desktop sign-in, update flow, and system-level interactions

## Boundaries to keep in mind

- Desktop-local capabilities and cloud capabilities are not always identical
- Some actions require approval, permissions, or desktop-only prerequisites
- Seeing a feature in configuration does not guarantee the runtime path is ready

## When the desktop app is the better choice

The desktop app is usually the better fit when:

- you want Deeting open as part of your daily workflow
- you need capabilities that are closer to the local runtime
- you care about tray behavior, notifications, and native desktop interactions
- you want a more integrated machine-level experience than the browser can provide

## If a feature looks available but does not run

Check these in order:

1. Is it a desktop-local capability or a cloud capability
2. Does it require approval, permissions, or environment setup
3. Is a model, plugin, or MCP dependency missing
4. If configuration looks correct, inspect transport, invoke contract, or local state next
