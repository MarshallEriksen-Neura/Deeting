# 飞书集成：事件与权限配置

为让 Deeting 机器人在飞书中有更好的体验，需在 **飞书开放平台** 为自建应用开启以下配置。

## 一、事件订阅（必开）

在 **开发者后台 → 应用 → 事件订阅** 中，建议订阅：

| 事件名称 | 说明 | 当前代码是否处理 |
|---------|------|------------------|
| **接收消息（v2.0）** `im.message.receive_v1` | 用户给机器人发消息（单聊、群聊 @ 机器人）时推送 | ✅ 是，核心能力 |
| **卡片回调（v2.0）** `card.action.trigger` / `card.action.trigger_v1` | 用户点击卡片按钮（有用/无用等）时推送 | ✅ 是 |
| **URL 验证** `url_verification` | 使用 Webhook 时飞书会发此事件做校验 | ✅ 仅校验用 |

- 若使用 **长连接（WebSocket）** 接收事件，只需在控制台勾选上述「接收消息 v2.0」「卡片回调 v2.0」即可，无需公网地址。
- 事件名称在文档里常写 `im.message.receive_v1`，在 v2.0 推送结构中仍是该类型名。

## 二、事件订阅（可选，提升体验）

| 事件名称 | 说明 | 用途建议 |
|---------|------|----------|
| **机器人被添加到群** `im.chat.member.bot.added_v1` | 机器人被加入群聊时 | 可发欢迎语、使用说明 |
| **用户加入群** `im.chat.member.user.added_v1` | 新成员入群时 | 可选欢迎或引导 @ 机器人 |
| **用户退群/被移出** `im.chat.member.user.deleted_v1` | 成员离开或移出群 | 做会话/上下文清理（若后续实现） |

当前代码未实现上述可选事件的处理逻辑，仅作配置参考；开启后不会报错，只是不会响应。

## 三、权限（必开）

在 **开发者后台 → 应用 → 权限管理** 中，至少开启：

- **机器人**
  - **获取用户发给机器人的单聊消息**（或「读取用户发给机器人的单聊消息」）
  - **获取群组中 @ 机器人的消息**（或「接收群聊中 @ 机器人消息」）
- 若希望机器人主动发消息、回复消息，还需：
  - **发送消息**（或「以应用身份发消息」）
  - **获取与发送图片、文件等**（若需要发图/文件时再开）

具体权限名称以控制台「权限管理」列表为准，以上为功能对应关系。

## 四、能力与可见范围

- **应用能力**：开启 **机器人**。
- **可用范围**：按需选择「全部员工」或指定部门/人员；测试阶段可先限制范围。

## 五、配置检查清单

- [ ] 事件订阅：接收消息 v2.0、卡片回调 v2.0 已勾选
- [ ] 权限：单聊消息、群 @ 机器人消息、发送消息 已开启
- [ ] 应用能力：机器人 已开启
- [ ] 若用 Webhook：`url_verification` 已配置且可访问

完成以上配置后，用户单聊或群聊 @ 机器人发文本消息、点击卡片按钮时，Deeting 才能正常收到并回复，获得与官方 OpenClaw 类似的对话与回复线程体验。

## 六、本地编排与工具（MCP / Skills）

飞书消息走的是 **同一套本地编排层**（`execute_local_orchestrated_chat`），与桌面端聊天一致：

- **控制面**：会做路由选择（`select_local_route`）、能力发现（语义检索本地 MCP 与 skills）、技能配方注入、能力提示等。
- **执行面**：根据路由结果可能是「仅回复」、「带推理/工具」或「代码模式」。当路由到 **WorkerReasoning** 或 **CodeModeOrchestration** 时，会带上 **search_sdk**、**execute_code_plan** 以及从能力快照里解析出的 **MCP 工具 / Skills**，模型可以发起工具调用并在多轮中执行。
- **工具解析与执行**：与桌面端相同，通过 `resolve_callable_mcp_tool_by_ref`、`resolve_skill_binding_by_ref` 等解析并执行本地配置的 MCP 与 skill 绑定。

因此：**本地配置的 MCP 和 Skills 在飞书里是可以被使用的**，并非「无法调用工具」；是否用上取决于当前用户消息触发的**路由结果**（简单问答可能走仅回复，需要查资料、执行操作等会走带工具的路径）。

**注意**：当前 IM 入口的 `max_tokens` 固定为 512（见 `handlers.rs` 中 `generate_local_chat_reply`）。若希望飞书里做较复杂的多轮工具链或长回复，可考虑将该值适当调大（如 1024 或 2048）。
